# Security policy

Run under a standard Windows user in an isolated research VM. Keep Defender, firewall and browser sandboxing enabled. A Python virtual environment isolates dependencies, not hostile code. Keep research separate from personal browser profiles and sensitive files.

All external responses are untrusted. Product data never becomes executable Python, shell commands or AI instructions. UI inputs cannot launch commands. HTTP adapters accept allowlisted HTTPS endpoints, check all resolved addresses, pin a public IP while preserving TLS hostname verification, reject redirects, ignore environment proxies and impose timeouts/bounded retries. HTTP responses are capped at 5 MiB after decompression; imports are 10 MiB/10,000 rows.

Best Buy native browsing runs normal site JavaScript inside sandboxed Chromium. Its hostname is pinned through Chromium resolver rules, other destinations are blocked, system proxies are disabled, and only same-origin GETs plus explicit read-only GraphQL queries are allowed. Account/purchase paths, mutations, third-party resources, downloads, websocket connections and non-read requests are blocked. Collection is bounded by page/product/request limits. Main-document size is checked after browser parsing; this is not a hard OS memory quota and browser asset allocation remains a residual risk. Generic/Amazon/AliExpress DOM parsing disables JS and all browser subresource traffic. No stealth, CAPTCHA solving, personal profile or stored browser login is used. Access denials/challenges stop collection.

No secrets belong in CSV, source settings, logs, SQLite or Git. Google OAuth is read only from environment variables and transmitted only by the official client to Google. Optional Best Buy API keys are kept in browser-session memory or process environment; that official API requires a query parameter, and request-level HTTP logging is disabled to prevent leakage. Keys are never included in exported products, source URLs/configuration or cached request bodies. Browser child environments remove application credentials, keys and proxy variables. Environment variables can still be inspected by a compromised same-user process. Rotate/revoke tokens and restart sessions/processes. Protect VM disks and backups.

Report vulnerabilities privately to the repository owner through an approved private channel or GitHub private vulnerability reporting if enabled. Do not post credentials, private datasets or exploit details in public issues. No response-time guarantee is established.

Known residual risks include browser/parser defects, malicious dependency updates, misleading merchant data, local account compromise, and incomplete heuristics for identity/demand. Defense in depth reduces risk; the application is not impossible to compromise. See docs/THREAT_MODEL.md.
